Drawing tools are an opt-in subpath export, so the core bundle never includes
them unless you import it. Attach them to a chart with `createAnnotations`:

```ts
import { createAnnotations } from '@lightfin/core/annotations'

const drawings = createAnnotations(chart)
drawings.setTool('trendline') // arm a tool; the user draws it
```

Every drawing anchors to data space (`{ time, price }` points), so it stays put
across pan, zoom, history backfill, and interval switches.

To get the drawing-tool and style toolbars for free, hand `drawings` to
[`createChrome`](/docs/api/chrome). Otherwise drive it from your own UI with the
API below.

## The tools

Each tool takes a fixed number of anchor points, placed in order:

<ToolCatalog />

A few that aren't obvious: `regression` fits a linear regression of the closes
between its two times (the points' prices are ignored); `longPosition` /
`shortPosition` take entry, target, and stop and show risk/reward; `brush` is a
freehand stroke sampled along a drag. Markers take a `shape` —
`'arrowUp' | 'arrowDown' | 'circle' | 'flag'`.

- `gannFan` starts at a pivot. Place its second anchor on the 1×1 ray to set
  the reference price change per bar. The other rays use time × price ratios
  relative to that slope, in the direction of the second anchor.
  [Gann Fan reference](https://www.metatrader5.com/en/terminal/help/objects/gann/gann_fan)
- `elliottImpulse` and `elliottCorrection` take the start of the sequence
  followed by each wave endpoint. The endpoints are labelled 1–5 and A–C,
  respectively. [Elliott Wave reference](https://www.elliottwave.com/free/introduction-to-the-wave-principle/)
- `headAndShoulders` takes the left shoulder, first reaction, head, second
  reaction, and right shoulder. The two reactions define the dashed neckline.
  Place the head and shoulders below the reactions for the inverse pattern.
  [Head and Shoulders reference](https://www.newyorkfed.org/medialibrary/media/research/staff_reports/sr4.pdf)

## `Annotations`

### Tools & modes

| Member                      | Notes                                                             |
| --------------------------- | ----------------------------------------------------------------- |
| `setTool(type, preset?)`    | Arm a tool (`null` for the cursor). `preset` seeds its style/shape — `setTool('trendline', { style: { extend: 'end' } })` draws rays. |
| `tool`                      | The armed tool, or `null`.                                        |
| `setStickyTool(on)`         | Keep the tool armed after each drawing (default: revert to cursor). |
| `setVisible(on)` / `visible`| Control global drawing visibility. Each drawing keeps its own `hidden` setting. |
| `setLocked(on)` / `locked`  | Lock all drawings against moving.                                |
| `select(id)` / `selected`   | Select a drawing or pass `null` to clear the selection. Hidden ids are ignored. |

### Reading & writing

| Member                      | Returns        | Notes                                             |
| --------------------------- | -------------- | ------------------------------------------------- |
| `add(input)`                | `string` (id)  | Add one drawing programmatically. Throws if malformed. |
| `load(inputs)`              | `void`         | Replace all drawings and reset undo history.      |
| `replace(group, inputs)`    | `string[]`     | Swap one group's drawings, leaving the rest. Validates all first. |
| `update(id, patch)`         | `void`         | Edit a drawing. Set `patch.hidden` to `true` to hide it or `false` to show it. Throws, changing nothing, if malformed. |
| `remove(id)`                | `void`         | Remove one drawing.                               |
| `clear(group?)`             | `void`         | Remove all drawings, or just one group's.         |
| `clone(id)`                 | `string \| null` | Duplicate a drawing, offset, visible, and selected. |
| `list(group?)` / `toJSON()` | `Annotation[]` | JSON-safe copies, oldest first. `toJSON()` is every drawing. |
| `get(id)`                   | `Annotation \| null` | One drawing.                                |
| `fibLevels(id)`             | `readonly number[] \| null` | Supported Fibonacci ratios for the drawing. |
| `effectiveStyle(id)`        | `AnnotationStyle \| null` | Its style with theme defaults filled in — for a style editor. |
| `bringToFront(id)` / `sendToBack(id)` | `void` | Reorder draw depth.                             |
| `editText(id)`              | `void`         | Edit a drawing's text/caption in place.           |

### History

`undo()` / `redo()` return `false` when there's nothing to do; `canUndo` /
`canRedo` are the booleans. History holds the last 100 changes.

### Events

```ts
const off = drawings.on('change', () => persist())
```

| Event              | Payload            | Fires when                                                   |
| ------------------ | ------------------ | ------------------------------------------------------------ |
| `change`           | —                  | The drawings changed, including visibility edits and undo/redo. Persist here. Fires once per drag and skips `load`. |
| `toolChange`       | `AnnotationType \| null` | The armed tool changed.                                |
| `selectionChange`  | `string \| null`   | The selected drawing's id.                                   |

Call `drawings.dispose()` to detach from the chart and drop listeners.

## Persistence

`createAnnotations(chart)` restores drawings from `localStorage` and saves
committed changes, including undo, redo, and deletion. The default key uses
the page, chart container, and the exchange and symbol set when you attach
annotations. Give your chart container a stable `id` or pass `persistenceKey`
to control where drawings are stored across mounts.

```ts
const drawings = createAnnotations(chart, {
  persistenceKey: 'my-app:drawings:BTCUSDT',
  onPersistenceError(error, operation) {
    console.error(`Could not ${operation} drawings`, error)
  },
})
```

To replace `localStorage`, pass a `DrawingPersistence` adapter as
`{ persistence: adapter }`. Both methods can return promises.

```ts
interface DrawingPersistence {
  load(): readonly AnnotationInput[] | null | Promise<readonly AnnotationInput[] | null>
  save(drawings: readonly Annotation[]): void | Promise<void>
}
```

Return `null` if no drawing list is stored. `save()` replaces the entire list,
including `[]` after clearing the chart. Lightfin validates the saved list
before restoring it. Use `await drawings.ready` before allowing edits if you
want users to start with the saved drawings. A committed edit made while the
initial read is pending takes precedence over the loaded list. Async saves
run in order, keeping the latest snapshot if more edits come in during a save.
`drawings.dispose()` disconnects the adapter when tearing down the chart.

Pass `{ persistence: false }` for in-memory drawings or to manage storage
directly with `toJSON()`, `load()`, and `on('change', …)`. An explicit call to
`load()` skips autosave. See [Saving and resetting settings](/docs/guides/saving-settings)
for an example that also persists chart settings.

## The `Annotation` shape

`toJSON()` returns an array of `Annotation` objects. `add()`, `load()`, and
`replace()` accept `AnnotationInput`, which makes `id` and `style` optional.

```ts
interface Annotation {
  id: string
  type: AnnotationType
  points: { time: UTCTimestamp; price: number }[]
  style: AnnotationStyle
  text?: string // a text/callout's label; on other types, a caption
  shape?: MarkerShape // a marker's shape; default 'circle'
  locked?: boolean // selectable but not movable by pointer
  hidden?: boolean // true hides this drawing. Defaults to false.
  hiddenLevels?: readonly number[] // Fibonacci ratios to hide
  group?: string // who placed it, e.g. 'ai'; the user's have none
}
```

`AnnotationStyle` is all-optional and falls back to the theme: `color`,
`lineWidth`, `lineStyle` (`'solid' | 'dashed' | 'dotted'`), `fillColor`,
`fontSize`, `fontFamily`, `bold`, `italic`, `textColor`, plus `extend` and
`arrow` (`'none' | 'start' | 'end' | 'both'`) for lines. `update()` takes an
`AnnotationPatch` with optional `points`, `style`, `text`, `shape`, `locked`, and
`hidden` fields, plus `hiddenLevels` for Fibonacci drawings. Set a `style`
field to `undefined` to restore its default.

Hide or show an individual drawing with `drawings.update(id, { hidden: true })`
or `drawings.update(id, { hidden: false })`. Hiding a selected drawing clears
the selection. Hidden drawings stay in `list()` and `toJSON()`, and visibility
changes can be undone and redone.

Use `drawings.fibLevels(id)` to get the available levels for a drawing, or use
the exported `FIB_LEVELS` and `FIB_EXTENSION_LEVELS` constants. Set
`drawings.update(id, { hiddenLevels: [0.5] })` to hide the `0.5` level, or pass
an empty array to show all levels. The hidden ratios are saved with the
drawing in `toJSON()`.

## Annotating from an AI

The `group` field lets one source own a slice of the drawings. An AI replaces
its whole set each turn, leaving the user's untouched:

```ts
drawings.replace('ai', [
  { type: 'hline', points: [{ time, price: 64_200 }], text: 'Support' },
  { type: 'marker', shape: 'arrowUp', points: [{ time, price: low }] },
])
```

`@lightfin/core/annotations/schema` ships a JSON Schema describing that input,
ready to hand a model as a tool definition — it's plain data in its own subpath,
so the drawing code never carries it:

```ts
import { annotateChartTool } from '@lightfin/core/annotations/schema'

// Anthropic: { name, description, input_schema: annotateChartTool.inputSchema }
// OpenAI:    { type: 'function', function: { name, parameters: annotateChartTool.inputSchema } }
// MCP:       annotateChartTool as-is

// When the model calls it:
try {
  drawings.replace('ai', input.annotations)
} catch (e) {
  // Return (e as Error).message to the model so it can fix and retry.
}
```

`annotationSchema` (the single-annotation schema) is exported too, and
`validateAnnotation` validates one input the same way `add()` does.
